# PSBees на общем сервере (несколько компьютеров)

Это **отдельный режим** PSBees: один сервер хранит учётные записи и проекты в SQLite,
сотрудники открывают его адрес в браузере со своих компьютеров. Устанавливать приложение
на каждый ПК не нужно. Обычный `bash run.sh`, `npm start` и Windows-приложение остаются
офлайн-редакторами без регистрации.

## Быстрый запуск в локальной сети

На **сервере**, где есть Node.js **22.13+** (рекомендуется 24), npm и репозиторий PSBees:

```bash
cd /path/to/linux_pcb_app
npm ci
npm run build

# Выберите ПОСТОЯННЫЙ каталог на диске сервера, вне dist/ и вне публичной раздачи.
# Не храните базу на временном диске и не добавляйте её в git.
export PSBEES_DATA_DIR="$HOME/psbees-data"
node scripts/cloud-admin.mjs create-admin admin@example.com
# Пароль вводится в терминале без отображения. Минимум 10 символов.

HOST=0.0.0.0 PORT=8080 npm run start:cloud
```

Откройте с другого компьютера `http://<IP-СЕРВЕРА>:8080/` (например,
`http://192.168.1.50:8080/`). Админ-панель: `http://<IP-СЕРВЕРА>:8080/admin`.
Администратор входит под указанной почтой и паролем. Пользователи выбирают
«Зарегистрироваться по почте» и входят со своими данными. Порт 8080 должен быть
разрешён в межсетевом экране, а IP сервера доступен компьютерам в сети.

> **Важно:** HTTP по сети передаёт пароль и сеансовый cookie незашифрованными.
> Для настоящих пользователей, даже внутри LAN, настройте HTTPS (ниже).
> Пример выше подходит для проверки в доверенной тестовой сети.

### Сохранение с компьютеров сотрудников

1. После входа нажмите **«Проекты» → «Сохранить копию»**. Проект получит имя,
   появится в личном списке и будет записан в базу на сервере.
2. У открытого облачного проекта изменения сохраняются автоматически через 1,8 секунды
   после прекращения редактирования. Статус виден в шапке и внизу редактора;
   `Ctrl+S` сохраняет его немедленно. Для новой платы `Ctrl+S` откроет список проектов.
3. На другом компьютере войдите в **ту же учётную запись** и откройте проект из списка.
   При одновременной работе с одной платой устаревшая версия не перезапишет новую:
   редактор покажет конфликт и предложит скачать свою копию, сохранить её новым
   проектом или загрузить актуальную версию.
4. Старый способ не исчез: «Открыть» загружает `.laypcb.json` / `.lay6` с компьютера,
   меню «Экспорт» → «Скачать проект файлом» скачивает JSON. Открытие файла или создание
   новой платы **не** перезаписывает ранее открытый облачный проект.

Проекты хранятся на сервере, а не у браузера. Несохранённый черновик облачного режима
остаётся только в текущей вкладке (`sessionStorage`); не закрывайте вкладку при ошибке
соединения без скачивания копии. **Личная библиотека деталей**, тема и настройки интерфейса
пока остаются в браузере; библиотека отделена по аккаунтам на одном ПК и переносится
кнопками «Экспорт/Импорт» в разделе «Детали». Состав уже установленных деталей входит
в JSON проекта и открывается на любом компьютере.

## Администрирование

Откройте `/admin` после входа администратором:

- **Обзор:** число пользователей, заблокированных, проектов, занятое место, сеансы;
  можно открыть/закрыть самостоятельную регистрацию.
- **Пользователи:** поиск, число и размер проектов, последний вход, блокировка и
  разблокировка, выдача/снятие роли администратора, отзыв всех сеансов, удаление
  аккаунта вместе с проектами. Себя и последнего активного администратора заблокировать
  или удалить нельзя.
- **Проекты:** поиск по названию/почте, фильтр владельца, скачивание любого проекта
  как `.laypcb.json`, удаление с подтверждением.
- **Журнал:** последние действия; хранится до 20 000 записей.

Если администратор забыл пароль, на самом **сервере** (не на пользовательском ПК):

```bash
export PSBEES_DATA_DIR="$HOME/psbees-data"  # тот же каталог, что у сервера
node scripts/cloud-admin.mjs reset-admin-password admin@example.com
```

Если пользователь забыл пароль, без удаления проектов задайте новый в терминале сервера:

```bash
export PSBEES_DATA_DIR="$HOME/psbees-data"
node scripts/cloud-admin.mjs reset-user-password user@example.com
```

Старые сеансы завершатся. Передайте пароль лично и попросите пользователя сменить его
через раздел «Учётная запись». Автоматического сброса пароля по email пока нет: SMTP
в PSBees **не настроен**. Регистрация принимает почту как логин, **не проверяет
владение адресом**.
Для реального подтверждения адресов нужен SMTP/внешний сервис; пока выдавайте доступ
в доверенной сети и, если нужно, закрывайте самостоятельную регистрацию в админке.

## Где лежат данные и как сделать резервную копию

`$PSBEES_DATA_DIR/psbees.sqlite` (и временные файлы SQLite `-wal`, `-shm`) содержат
проекты, хэши паролей, настройки регистрации и журнал. Сервер создаёт каталог
с правами `0700` (если существующий каталог открыт другим пользователям ОС — запуск
отклоняется), файл базы — `0600`. Запускайте сервис не от root и делайте бэкапы.
База работает в WAL-режиме: **не копируйте один `.sqlite` файл `cp` во время работы**.

- Вариант 1: остановить сервер, скопировать **весь каталог** (включая `-wal` и `-shm`),
  затем запустить сервер.
- Вариант 2: на работающем сервере использовать команду SQLite Online Backup
  (`sqlite3` устанавливается отдельно), например:

```bash
mkdir -p "$HOME/psbees-backups" && chmod 700 "$HOME/psbees-backups"
sqlite3 "$PSBEES_DATA_DIR/psbees.sqlite" \
  ".backup '$HOME/psbees-backups/psbees-$(date +%F).sqlite'"
```

Проверяйте восстановление на **отдельном** сервере и храните копии вне компьютера с
основной базой. Для переноса достаточно файла резервной копии SQLite (запустить PSBees
с указанием нового `PSBEES_DATA_DIR`, содержащего `psbees.sqlite`).

По умолчанию один проект — до **8 МиБ**, аккаунт — до **250 МиБ / 1000 проектов**.
Лимит аккаунта можно поднять до запуска:

```bash
PSBEES_DATA_DIR="$HOME/psbees-data" PSBEES_USER_QUOTA_MB=1000 npm run start:cloud
```

Один процесс PSBees обслуживает все компьютеры. Не запускайте несколько процессов с
одинаковой базой за балансировщиком: ограничения входа считаются в памяти процесса.
SQLite корректно сохраняет параллельные запросы, конфликты версий обрабатываются API.

## Постоянная работа и HTTPS

Для постоянной работы настройте systemd, обратный прокси с TLS (например Caddy/nginx)
и ограничьте доступ к серверу. Пример для Ubuntu с установленным системным Node.js 24:

```ini
# /etc/systemd/system/psbees.service
[Unit]
Description=PSBees shared server
After=network.target

[Service]
Type=simple
User=psbees
WorkingDirectory=/opt/psbees
Environment=PSBEES_DATA_DIR=/var/lib/psbees
Environment=PSBEES_SECURE_COOKIES=1
Environment=PSBEES_TRUST_PROXY=1
Environment=HOST=127.0.0.1
Environment=PORT=8080
ExecStart=/usr/bin/node /opt/psbees/scripts/server.mjs --cloud
Restart=on-failure
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

Создайте системного пользователя `psbees` и каталог `/var/lib/psbees` с владельцем
`psbees` и правами `0700`; соберите `dist` заранее, создайте администратора от имени
`psbees` из интерактивного терминала. `/opt/psbees` содержит исходники/сборку; база
остаётся в `/var/lib/psbees` и не пропадает при обновлении кода. Затем
`sudo systemctl daemon-reload && sudo systemctl enable --now psbees`.

Пример Caddyfile для внутреннего DNS-имени (сертификату `tls internal` нужно доверять
на **каждом** клиентском компьютере):

```caddyfile
pcb.office.lan {
    tls internal
    reverse_proxy 127.0.0.1:8080
}
```

Если у вас есть доменное имя и публичный сертификат — используйте его вместо
`tls internal`. Прокси должен передавать исходный `Host` (либо `X-Forwarded-Host`)
и `X-Forwarded-Proto`;
не открывайте порт 8080 наружу при конфигурации с `HOST=127.0.0.1` и
`PSBEES_TRUST_PROXY=1`. Иначе удалённый клиент сможет подделать свой IP в
`X-Forwarded-For`. В интерфейсе и API используются относительные URL, поэтому
пользовательские браузеры обращаются к адресу сервера, а не к `localhost`.

В режиме разработки `PSBEES_CLOUD_BACKEND=http://127.0.0.1:8080 npm run dev`
проксирует `/api/cloud/*` на запущенный отдельно общий сервер. Без этой переменной
Vite остаётся обычным локальным редактором.

**Обновление:** остановите сервис, сделайте бэкап, обновите код, запустите `npm ci &&
npm run build`, затем снова запустите сервис. HTTP-команды `/update/*` на общем сервере
заблокированы: обычные пользователи не могут обновить исполняемый код.
