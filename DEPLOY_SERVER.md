# PSBees на общем сервере Ubuntu

Один сервер обслуживает браузеры всех компьютеров в локальной сети: хранит учётные записи,
платы и историю проектов. Устанавливать редактор на рабочие станции не нужно.
На сервере используется отдельный системный пользователь, SQLite вне веб-каталога,
автозапуск `systemd`, почтовая двухфакторная аутентификация и приглашение редактора
к совместной плате.

## Установка и первый запуск одним файлом

Подключитесь к Ubuntu-серверу по SSH или откройте терминал. Нужен git, чтобы скачать
проект; установщик сам добавит Node.js 24 LTS, зависимости и systemd-службу.

```bash
git clone https://github.com/danilka-revin/linux_pcb_app.git ~/linux_pcb_app
cd ~/linux_pcb_app
sudo bash server-ubuntu.sh install
```

Установщик задаст SMTP-настройки, проверит соединение без отправки тестового письма,
попросит почту первого администратора и безопасно запросит пароль (ввод скрыт).
Запускайте установку из интерактивного SSH-сеанса или консоли Ubuntu: пароль первого
администратора нельзя передать аргументом командной строки или через файл проекта.
После этого скрипт соберёт приложение, создаст systemd-пользователя `psbees`, запустит
сервер при старте Ubuntu и выведет адреса. Данные не лежат в папке кода и не удаляются
при обновлении.

По умолчанию:

- приложение: `/opt/psbees`;
- база и данные: `/var/lib/psbees/psbees.sqlite` (каталог `0700`, файл `0600`);
- SMTP-секреты: `/etc/psbees/psbees.env` (доступ только root);
- адрес: порт `8080`, интерфейс `0.0.0.0`;
- служба: `psbees.service`, работает не от root.

Откройте с компьютеров в LAN адрес из вывода установщика, например
`http://192.168.1.50:8080/`. Админ-панель — `http://192.168.1.50:8080/admin`.
Если UFW уже включён, скрипт по умолчанию разрешает RFC1918 IPv4 и явно запрещает
остальные источники на выбранном TCP-порту; свой диапазон можно указать через
`PSBEES_LAN_CIDR=192.168.1.0/24`. Скрипт намеренно не включает
выключенный firewall, чтобы случайно не потерять SSH; включите и настройте firewall
самостоятельно. IPv6 LAN нужно настроить отдельно. Не делайте проброс порта 8080
с роутера в интернет.

### SMTP для кодов 2FA

Рабочий SMTP обязателен: сервер не стартует в cloud-режиме без настройки почты.
Код из письма нужен **при регистрации и при каждом новом входе**; сессия действует
14 дней. Код одноразовый, действует 10 минут, после пяти ошибочных вводов его нужно
запросить заново. SMTP можно взять у почтового провайдера или организации; если сервер
разрешён по IP, логин/пароль можно оставить пустыми. SMTP relay всё равно должен
поддерживать TLS/STARTTLS — соединение без TLS сервер не использует.

Конфигурация хранится в `/etc/psbees/psbees.env`: `PSBEES_SMTP_HOST`, `PORT`, `SECURE`,
`FROM`, а при необходимости — `USER` и `PASS`. Для изменения отредактируйте этот файл
от root и перезапустите службу:

```bash
sudoedit /etc/psbees/psbees.env
sudo bash server-ubuntu.sh smtp-check
sudo systemctl restart psbees
sudo journalctl -u psbees -n 50 --no-pager
```

Не помещайте SMTP-пароль в репозиторий, скрипт запуска, командную строку или общий чат.
Если пароль с пробелами/кавычками, оставьте формат кавычек systemd, созданный установщиком.

## Пользователи и совместное редактирование платы вдвоём

1. Администратор входит по своей почте и паролю, вводит одноразовый код из письма.
   Другие сотрудники выбирают **«Зарегистрироваться по почте»**, задают пароль и
   подтверждают адрес кодом. Вход только по паролю не создаёт сессию.
2. Владелец открывает **«Проекты» → «Сохранить копию»**, затем напротив платы нажимает
   **«Участники»** и вводит почту уже зарегистрированного коллеги.
3. Коллега входит с другого компьютера, открывает **«Проекты»** и плату с отметкой
   **«Общая»**. Его изменения автоматически сохраняются, другой редактор получает их
   почти сразу; число активных участников видно в шапке редактора.
4. Доступ можно отозвать в том же списке. К плате подключается владелец и один редактор
   (всего два пользователя). Совместные участники редактируют документ, просматривают
   именованные версии и могут сохранить отдельную копию. Переименование и удаление
   общей платы остаются у владельца.

Синхронизация использует серверные ревизии и трёхстороннее слияние. Изменения разных
объектов и независимых полей объединяются; если два человека одновременно поменяли
одно и то же свойство объекта, сервер не перезапишет одну правку молча — приложение
покажет конфликт и предложит скачать локальную копию или загрузить серверную версию.

Владельцу принадлежат квота проекта и версии. По умолчанию плата — до **8 МиБ**,
пользователь — до **250 МиБ / 1000 собственных проектов**; общая плата видна в списке
обоих участников. Личные библиотеки деталей и настройки интерфейса остаются в браузере
каждого пользователя; вкладка «Общая» хранится в SQLite сервера и одинакова для всех
пользователей этого рабочего пространства. Элементы публикуются автором из личной библиотеки,
а удалить опубликованное может автор или администратор. Защита хранилища ограничивает одну
деталь 512 КиБ, личный вклад — 1000 деталей / 32 МиБ, а библиотеку сервера — 10 000 деталей / 512 МиБ.

## Администрирование и команды сервера

`/admin` доступна только вошедшему администратору (проверка роли выполняется и в API).
Сводка пользователя показывает подтверждение почты/2FA, его собственные и общие проекты,
версии, объём данных, активные сеансы и недавние события. Администратор не может увидеть
исходный пароль или его хеш: в списке пользователя можно выдать временный пароль, который
показывается один раз, отзывает его старые сеансы и обязывает сменить пароль перед работой.
В панели также доступны блокировка, роли, удаление аккаунта, проекты, JSON и журнал действий.
Самостоятельную регистрацию можно закрыть. Администратор не может заблокировать или
удалить свою учётную запись, если он последний активный администратор.

Управление одной командой из клона проекта:

```bash
sudo bash server-ubuntu.sh status
sudo bash server-ubuntu.sh logs
sudo bash server-ubuntu.sh smtp-check
sudo bash server-ubuntu.sh restart
sudo bash server-ubuntu.sh update
sudo bash server-ubuntu.sh backup
```

`update` пересобирает код и перезапускает службу, не трогая базу и пользователей.
Скрипт собирает текущую копию репозитория — сначала обновите/проверьте исходники,
если хотите поставить более новую версию. `backup` безопасно останавливает службу,
архивирует весь каталог SQLite (включая WAL) в `/var/backups/psbees/`, затем запускает её.
Резервные копии закрыты правами `0600`; перенесите их с сервера и регулярно проверьте
восстановление на отдельной машине. Для аварийного восстановления стандартного каталога
(сначала остановите службу и сохраните старую БД отдельно):

```bash
sudo systemctl stop psbees
sudo mv /var/lib/psbees /var/lib/psbees.before-restore
sudo tar -xzf /var/backups/psbees/ИМЯ-КОПИИ.tar.gz -C /var/lib
sudo chown -R psbees:psbees /var/lib/psbees
sudo chmod 0700 /var/lib/psbees
sudo systemctl start psbees
```

Если настроен другой `PSBEES_DATA_DIR`, замените в командах `/var/lib` и `psbees` на
его родительский каталог и имя; каталог из архива сохраняет исходное имя.

Сброс пароля вручную на самом Ubuntu-сервере, не удаляя проекты:

```bash
sudo -u psbees env PSBEES_DATA_DIR=/var/lib/psbees \
  /usr/bin/node /opt/psbees/scripts/cloud-admin.mjs reset-admin-password admin@example.com
sudo -u psbees env PSBEES_DATA_DIR=/var/lib/psbees \
  /usr/bin/node /opt/psbees/scripts/cloud-admin.mjs reset-user-password user@example.com
```

Новый пароль вводится в интерактивном терминале скрыто, старые сессии отзываются.
После `reset-user-password` при первом входе пользователь обязан заменить заданный пароль;
после `reset-admin-password` администратор входит с новым паролем и email-кодом 2FA.

## HTTPS и безопасность в рабочей сети

Установка по умолчанию обслуживает **HTTP** для быстрого запуска в доверенной LAN.
На HTTP пароль и cookie не зашифрованы; 2FA по почте не защищает от перехвата этих
данных внутри сети. Для постоянного использования включите TLS через reverse proxy
(Caddy, nginx) или доверенную корпоративную инфраструктуру. Если сертификат
самоподписан/внутренний, установите корневой сертификат на клиентские компьютеры.

Пример Caddyfile для внутреннего DNS-имени:

```caddyfile
pcb.office.lan {
    tls internal
    reverse_proxy 127.0.0.1:8080
}
```

Для этой схемы измените `/etc/psbees/psbees.env`:

```ini
HOST="127.0.0.1"
PSBEES_TRUST_PROXY=1
PSBEES_SECURE_COOKIES=1
```

и выполните `sudo systemctl restart psbees`. Не оставляйте порт 8080 открытым для
клиентской сети, когда backend должен принимать запросы только от локального proxy.
Прокси должен передавать исходные `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto`;
доверенный `X-Forwarded-For` включайте только если backend изолирован от прямого доступа.
Если UFW включён, отдельно разрешите LAN-подключения к порту reverse proxy (например,
`sudo ufw allow from 192.168.1.0/24 to any port 443 proto tcp`); PSBees намеренно
настраивает только свой backend-порт. Пользовательский браузер обращается к относительным
URL того же сервера — настройки `localhost` на клиентских ПК не нужны.

## Ручной режим разработки

Для локального теста (не как постоянная systemd-служба) можно запустить собранный сервер
с SMTP-переменными окружения:

```bash
npm ci && npm run build
export PSBEES_DATA_DIR="$HOME/psbees-data"
export PSBEES_SMTP_HOST=smtp.example.com PSBEES_SMTP_PORT=587 PSBEES_SMTP_SECURE=0
export PSBEES_SMTP_FROM=pcb@example.com PSBEES_SMTP_USER=pcb@example.com
read -r -s -p 'SMTP пароль: ' PSBEES_SMTP_PASS; echo; export PSBEES_SMTP_PASS
node scripts/cloud-admin.mjs create-admin admin@example.com
HOST=0.0.0.0 PORT=8080 npm run start:cloud
```

Один процесс обслуживает все браузеры. Не запускайте несколько экземпляров с общей SQLite
за балансировщиком: long-poll и онлайн-статус участников хранятся в памяти процесса.

## Тесты

`npm run test:cloud` покрывает SMTP OTP-flow (с безопасной тестовой почтой), права проектов,
приглашение/отзыв участника, общую библиотеку деталей и права публикации, независимые и
конфликтующие одновременные правки, long-poll, SQLite, перезапуск и административные операции. `npm run test:server` проверяет HTTP,
статическую установку и базовые маршруты.
